## 결정

Nginx·앱·MySQL·Redis를 Lightsail 한 대에서 운영한다. GitHub Actions가 SHA 태그로 이미지를 발행하고 관리자가 배포할 커밋을 선택한다. 새 릴리스가 기동하지 못하면 배포 스크립트가 직전 정상 버전으로 복구한다. [배포 절차](../../deploy/README.md)

## 11월 24일 후속 수정과 로컬 검증

배포 PR 두 곳의 중간 커밋에서 같은 동시 실행 테스트가 실패했다. 실제 MySQL에서 두 요청을 겹쳐 보니 멤버의 일정 확인은 멤버 행을 잠근 채 방의 활동 시각 갱신을 기다렸고, 방장 탈퇴는 방 행을 잠근 채 같은 멤버의 삭제를 기다렸다. MySQL은 일정 확인 요청을 롤백했다. [단일 서버 PR의 실패](https://github.com/Central-MakeUs/TripFit-server/actions/runs/45140388890/job/137576637006) · [Terraform PR의 실패](https://github.com/Central-MakeUs/TripFit-server/actions/runs/45140398313/job/137576670552)

| 수정 | 확인한 결과 |
|---|---|
| 여행방 잠금 | 일정 확인·강퇴·방 나가기가 멤버 상태를 변경하기 전에 방을 잠그도록 수정했다. 같은 방의 일정 확인과 방장 탈퇴를 250회 겹쳐 실행해 잠금 실패가 없었다. |
| 로컬 HTTP 게이트웨이 | 루트 Compose의 `edge`가 실제 로컬 서버 설정을 읽고 IPv4에서 상태를 확인하도록 고쳤다. 별도 Compose 프로젝트에서 MySQL과 기존 로컬 앱 이미지를 기동했다. Nginx 설정 검사, `/health` 응답, 외부 Actuator 경로의 404, 프록시를 통한 OpenAPI 32개 경로 조회를 확인했다. |
| 이미지 발행 | `main`의 두 선행 작업 성공 의존성과 워크플로 문법을 검사했다. 기준 명세 조회·도구 설치·스냅샷 push의 실패 처리는 모의 명령으로 확인했다. 로컬에서 웹훅을 대체해 경로 하나를 제거했을 때 일반 발송은 1회, PR 병합 모드는 0회임을 확인했다. 같은 명세에서는 두 경우 모두 알림이 없다. |

### 잠금과 탈퇴 회귀 테스트

Docker를 기동하고 `./gradlew test --tests '*UserWithdrawalLockOrderIntegrationTest' --rerun-tasks`로 아래 케이스를 실행할 수 있다. SQL 순서 테스트는 행을 잠그는 문장이 멤버 변경보다 먼저 실행됐는지 확인한다.

| 실제 MySQL에서 검사한 요청 | 수정 전 | 수정 후 | 해당 수정만 되돌렸을 때 |
|---|---|---|---|
| 멤버의 일정 확인 완료 | 방을 먼저 잠그는 SQL이 없어 실패 | 통과 | 실패 |
| 방장의 멤버 강퇴 | 방을 먼저 잠그는 SQL이 없어 실패 | 통과 | 실패 |
| 일반 멤버의 계정 탈퇴 | 방을 먼저 잠그는 SQL이 없어 실패 | 통과 | 실패 |
| 계정 탈퇴 중 방장이 먼저 방 삭제 | 잠금 추가 후 방을 찾을 수 없어 탈퇴 전체가 실패 | 계정 삭제 완료, 삭제된 방의 활동 시각 보존 | 방 삭제를 건너뛰는 조건을 빼면 탈퇴 실패 |

수정 전 전체 테스트는 543개가 통과했다. 최종 전체 테스트는 547개가 통과했고 실패·건너뜀은 0개였다. Gradle 빌드와 서식 검사, `actionlint`, 문서의 내부 링크 검사를 통과했다. 다시 생성한 OpenAPI와 저장소 스냅샷의 내용은 일치했다.

이번 후속 검증은 로컬에서 수행했다. 원격 GitHub Actions의 이미지 발행과 운영 배포 결과는 다음 릴리스 때 확인할 수 있다.
