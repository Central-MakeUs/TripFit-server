# 공휴일 API 연동 가이드 (공공데이터포털 특일 정보)

대한민국 공휴일·대체공휴일을 서버가 자동으로 받아오게 하는 **1회성 설정 절차**입니다.

| 관련 문서 | 용도 |
|-----------|------|
| [`docs/decisions/011-holiday-data-source.md`](../docs/decisions/011-holiday-data-source.md) | 왜 static table이 아니라 이 API를 골랐는지 |
| [`docs/specs/user-schedule/schedule-holiday-rest.md`](../docs/specs/user-schedule/schedule-holiday-rest.md) | 공휴일이 근무일 판정에 어떻게 반영되는지 |
| [`README.md`](README.md) 환경 변수 절 | `HOLIDAY_API_SERVICE_KEY`를 포함한 전체 Secret 목록 |

**키가 없어도 서버는 정상 기동한다.** 키가 비어 있으면 동기화를 건너뛰고 "공휴일이 하나도 없는 상태"로 동작할 뿐이다(달력·추천은 그대로 작동하되, 공휴일에 쉬는 사람도 그날 근무로 계산된다). 즉 이 설정은 **기능을 켜는 스위치**이지, 배포를 막는 필수 조건이 아니다.

---

## 1단계 — 공공데이터포털 활용신청

1. [공공데이터포털](https://www.data.go.kr) 회원가입 · 로그인
2. 검색창에 **`특일 정보`** 입력 → **한국천문연구원_특일 정보** (오픈 API) 선택
3. 우측 **[활용신청]** 클릭
4. 신청 양식 작성
   - **활용목적**: `웹 사이트 개발` (또는 `앱 개발`)
   - **상세 기능정보**: 목록 중 **`getRestDeInfo`(국경일 및 공휴일 정보조회)** 를 **반드시 체크**
     - ⚠️ `getHoliDeInfo`(국경일)만 체크하면 **대체공휴일이 빠진다.** 서버가 호출하는 건 `getRestDeInfo`다.
5. 신청 완료 → **개발계정은 보통 즉시 자동 승인**된다 (승인 대기가 걸리면 몇 시간~1영업일)

**트래픽 한도:** 개발계정 기준 일 1,000회. 서버는 하루 1회 × 3개년 = **하루 3회**만 호출하므로 한도 걱정은 없다.

---

## 2단계 — 인증키 복사 (⚠️ Decoding 키)

마이페이지 → **데이터활용 → 오픈 API → 개발계정** → 신청한 API 상세로 들어가면 인증키가 **두 가지 형태**로 보인다.

| 형태 | 생김새 | TripFit에 넣을 값 |
|------|--------|-------------------|
| Encoding | `%2BabcD...%3D%3D` (`%2B`, `%3D` 등이 섞임) | ❌ |
| **Decoding** | `+abcD.../==` (`+`, `/`, `=` 원문 그대로) | ✅ **이걸 복사** |

**왜 Decoding인가:** 서버가 요청을 보낼 때 URL 인코딩을 한 번 자동으로 한다. 여기에 이미 인코딩된 Encoding 키를 넣으면 `%2B`가 `%252B`로 **두 번 인코딩**돼 포털이 "등록되지 않은 키"로 판단한다. 국내에서 이 API를 붙일 때 가장 흔한 실패 원인이다.

---

## 3단계 — 키 등록

### 운영 서버 (배포)

GitHub repo → **Settings → Secrets and variables → Actions → New repository secret**

| 항목 | 값 |
|------|-----|
| Name | `HOLIDAY_API_SERVICE_KEY` |
| Secret | 2단계에서 복사한 **Decoding** 키 |

등록 후 `main`에 push(또는 CI/CD 워크플로 재실행)하면 값이 컨테이너까지 자동으로 전달된다 — EC2에 SSH로 들어가 `.env`를 고칠 필요 없다.

### 로컬 개발

루트 `.env`에 추가한다 (`.env.example` 참고).

```bash
HOLIDAY_API_SERVICE_KEY=여기에_Decoding_키
```

로컬에서 공휴일까지 확인할 필요가 없다면 **비워둬도 된다.**

## 4단계 — 동작 확인

키를 넣고 서버를 재시작하면 **기동 직후 1회** 동기화가 돈다(이후 하루 1회). 로그로 확인한다.

```bash
docker compose logs app | grep -i 공휴일
```

| 로그 | 의미 | 조치 |
|------|------|------|
| (공휴일 관련 로그 없음) | 정상 — 3개년 동기화 성공 | 없음 |
| `공휴일 API 인증키가 없어 동기화를 건너뜀` | 키가 전달되지 않음 | Secret 이름 오타·워크플로 재실행 여부 확인 |
| `공휴일 {연도}년 동기화 실패 — 기존 캐시 유지` | API 호출 실패 | 대부분 **Encoding 키를 넣은 경우** (2단계). 활용신청 승인 여부도 확인 |
| `공휴일 {연도}년 응답이 비어 있어 캐시를 갱신하지 않음` | 호출은 됐지만 결과가 0건 | `getRestDeInfo` 기능이 활용신청에 포함됐는지 확인 (1단계 4번) |

**데이터로 직접 확인** (EC2 D Redis 접근 가능한 환경에서):

```bash
redis-cli -h "$REDIS_HOST" -a "$REDIS_PASSWORD" SMEMBERS holiday:kr:2026
```

`20260101`, `20261003`, `20261005`, `20261009` … 형태의 날짜 목록이 나오면 정상이다.

**앱에서 확인:** 정기 일정을 `월~금 09:00~18:00` + `공휴일에 쉼`으로 등록한 계정으로 마이페이지 달력에서 **한글날(10/9, 금)** 을 본다. 근무로 막혀 있지 않고 하루 종일 비어 있으면 반영된 것이다.

## 키 발급 전에 확인할 것 — 스펙 대조

인증키를 처음 발급받았다면, **실제 응답을 한 번 눈으로 확인**하고 스펙의 "외부 API" 절과 대조한다. 응답 필드가 스펙과 다르면 **코드를 고치기 전에 스펙을 먼저 수정**한다.

```bash
curl "https://apis.data.go.kr/B090041/openapi/service/SpcdeInfoService/getRestDeInfo?serviceKey=발급받은_Decoding_키&solYear=2026&numOfRows=100&_type=json"
```

기대 형태 (`response.body.items.item[]`):

```json
{"dateKind": "01", "dateName": "한글날", "isHoliday": "Y", "locdate": 20261009, "seq": 1}
```

서버는 이 중 **`isHoliday`가 `Y`인 항목의 `locdate`** 만 사용한다.

## 장애 시 동작 (알아두면 좋은 것)

| 상황 | 서버 동작 |
|------|-----------|
| 공공데이터포털 API가 죽음 | 기존 Redis 캐시를 계속 사용. 7일 이상 연속 실패하면 캐시가 만료돼 "공휴일 없음"으로 degrade |
| Redis가 죽음 | 즉시 "공휴일 없음"으로 간주하고 달력·추천은 그대로 응답(fail-open) — 화면이 죽지 않는다 |
| 임시공휴일이 새로 지정됨 | 다음 날 동기화에서 자동 반영 (최대 24시간 지연) |

어느 경우에도 사용자에게 에러가 뜨지 않고, "공휴일을 모르는 상태"로만 성능이 떨어진다.
